## 一、项目概述

### 1\.1 项目定位

本项目是一款基于 Three\.js 的三维可视化时间管理 Web 应用。

通过“盖楼”的形式，将用户的日常活动与时间记录转化为一栋不断向上生长的三维建筑。

每层楼代表一项活动，房间内的三维场景与主角小猫共同呈现用户当天的生活。

### 1\.2 核心概念

**把一天的时间建成一栋楼。**

用户从当天的第一项活动开始记录，每完成一项活动，建筑就增加一层。

一天结束后，整栋建筑成为用户当天生活的三维记录。

### 1\.3 核心创新点

1. 将传统的时间记录转化为可持续生长的三维建筑。

2. 通过不同的建筑表现形式，实现行为记录、时间可视化与未来规划。

3. 采用具有情感化特征的小猫角色，增强记录行为的趣味性与陪伴感。

4. 使用模块化三维场景和可复用资产，降低实时生成场景的成本。

## 二、核心功能设计

### 2\.1 记录模式/真实模式（Record Mode/True Mode）

**定位：记录实际发生的活动，形成精细三维建筑。**

功能：

- 用户选择活动类型（8大场景之一）、可选正直接开始、倒计时输入时间。

- 系统根据活动类型匹配场景。

- 自动在建筑顶部生成一个新楼层，播放小猫走进楼左侧电梯，上升进入到新楼层、电梯间相应伸长的动画

* [ ] 详细动画效果确定

- 所有建起的楼层保持相同高度。

- 小猫在房间中展示与活动对应的动作。

- 点击该楼层，房间放大到铺满屏幕，沉浸式大房间；

- 房间部分物品可交互，例如点击墙上挂钟，挂钟会放大让用户查看时间（其他交互待定）

* [ ] 房间物件交互

- 下方的楼层中小猫刚才进行的活动，相关物件需要复原，例如刚正在睡觉，则床的状态要由睡觉→铺好。

视觉特点：

- 固定正面剖面视角。

- 精细三维家具与场景。

- 统一的房间结构和建筑风格。

- 注重光影、材质、动画与交互细节。

初期预设八类场景：

睡觉、吃饭、学习/工作、室外自然、通勤、社交、居家、娱乐

### 2\.2 展开模式（Expanded Mode）

**定位：通过建筑高度呈现一天的时间分配。**

功能：

- 用户可从记录模式切换至展开模式。

- 每层楼的高度根据活动时长重新计算。

- 设置最大层高和最小层高。

- 通过建筑高度展示不同活动的时间占比。

- 房间内部使用醒目的艺术字体展示活动和时长。

- 支持切换回记录模式。

- 【可选】展开后房间加入“复式楼”家具，楼梯、壁挂装饰、壁画等

视觉特点：

- 建筑沿垂直方向拉伸或压缩。

- 地面家具保持在底部。

- 吊灯等悬挂资产保持在顶部。

- 中间留出文字展示区域。

- 采用平滑的楼层高度变化动画。

### 2\.3 蓝图建造功能（Blueprint）

**定位：帮助用户提前规划未来一天的活动。**

功能：

- 用户提前制定未来的活动计划，房间呈“锁定状态”。

- 输入预计活动内容、时长，系统先生成房间（和记录模式一样一层层往上盖），**然后给房间外侧加一层磨砂玻璃【视觉风格如下】**

## 三、整体交互流程

### 3\.1 计划阶段

用户选择活动类型 → 规定时间→ 系统生成蓝图建筑。

### 3\.2 记录阶段

用户输入实际活动 → 选择活动类别与时间 → 系统生成对应楼层 → 建筑持续增长。

### 3\.3 回顾阶段

一天结束 → 查看完整建筑 → 切换展开模式 → 查看时间分配 → 对照原定蓝图。

### 3\.4 基础交互

- 新增、修改、删除活动。

- 查看楼层信息。

- 切换三种模式。

- 浏览完整建筑。

- 选择历史日期。

- 查看当天计划与实际记录。

## 四、三维场景与美术设计

### 4\.1 建筑系统

- 使用模块化的内凹房间作为基本建筑单元。

- 房间在 Three\.js 中沿垂直方向堆叠。

- 记录模式采用统一层高。

- 展开模式使用可变高度。

- 蓝图模式本质就是“锁定状态”的玻璃封锁的房间。

### 4\.2 场景资产

- 预设8类基础活动场景。

- 每类场景具有独立的家具组合。

- 家具采用 GLB 等格式导入。

- 后期可逐步扩充资产库。

- 不依赖大模型 API 实时生成房间。

### 4\.3 小猫角色

- 第一版先固定一只小猫形象。

- 小猫代表用户本人。

- 根据活动类型切换动作。

- 保持角色在不同场景中的一致性。

### 4\.4 视觉风格

- 固定正面剖面视角。

- 微缩建筑 / Dollhouse 风格。

- 强调各房间的独立氛围。

- 统一的整体建筑语言。

- 记录模式强调场景细节，展开模式强调信息表现，蓝图模式强调结构表达。

## 五、技术实现方案

### 5\.1 前端技术

- React \+ Vite

- Three\.js

- React Three Fiber

- Drei

### 5\.2 三维模型工作流

1. 使用 Rhino 或 Three\.js 制作标准房间结构。

2. 使用 Lux 3D、Blender MCP 等工具制作家具及细节资产。

3. 将资产整理并导出为 GLB。

4. 通过 Three\.js 加载与组装。

5. 通过配置数据控制楼层和场景内容。

### 5\.3 场景生成系统

- 根据活动类别选择预设房间。

- 根据时间数据计算楼层位置及高度。

- 使用统一组件管理建筑。

- 通过配置文件管理家具位置与灯光。

- 使用预设动画控制小猫行为。

### 5\.4 数据管理

记录以下信息：

- 日期

- 活动名称

- 活动类型

- 开始时间

- 结束时间

- 活动时长

- 计划或实际状态

- 对应场景配置

初期使用本地存储，后期根据需要加入数据库及用户账户系统。

## 八、预期成果

最终形成一款具有以下特点的 Web 应用：

1. 用户可以通过记录活动持续建造属于自己的三维建筑。
